# マージ済みブランチの片付け

作業分割で切ったブランチは、最終確認が済むまで残す運用になっている
(グローバル CLAUDE.md「作業分割の手順」)。確認が済んだら本スキルで一括して片付ける。

| 種類 | 名前 | 既定で対象か |
|---|---|---|
| 分割しない作業 | `[種別]/[名前]` | 対象 |
| 親ブランチ | `[種別]/[名前]/main` | 対象 |
| サブブランチ | `[種別]/[親の名前]/sub/[種別]/[名前]` | 対象 |
| 接頭辞付き | `spike/...`、`wip/...`(上記の先頭に付けたもの) | 名指ししたときだけ |

`[種別]` は `feature|bugfix|fix|chore|refactor|docs|test` のいずれか。

判定は目視ではなく `cleanup-merged-branches.sh` に任せる。ブランチ名や PR の見た目ではなく
**コミットの突合**で「取り込み済み」を確定させるため。

```sh
# 一覧だけ出す(既定は dry-run)
~/.claude/skills/git-branch-cleanup/cleanup-merged-branches.sh

# 実際に削除する。リモート(origin)側も消すなら --remote
~/.claude/skills/git-branch-cleanup/cleanup-merged-branches.sh --apply --remote
```

## 取り込み済みの判定(3段)

上から順に判定し、当たった時点で確定する。どれにも当たらなければ `KEEP` で残す。

| 段 | 判定 | 当たるケース |
|---|---|---|
| `ancestor` | ブランチ先端が base の祖先(`git merge-base --is-ancestor`) | マージコミット / 早送り / リベースマージ |
| `patch-id` | `git cherry base branch` が全行 `-` | cherry-pick、単一コミットの squash |
| `pr` | `gh pr list --state merged --head <branch>` に該当あり | 複数コミットの squash マージ |

`ancestor` のときは `git rev-list --ancestry-path <branch>..<base> | tail -1` で
**base 側で最初にそのブランチを取り込んだコミット**を出し、根拠として表示する。
`pr` のときは PR 番号とマージコミットを表示する。

## 削除の順序と方法

1. ブランチがワークツリーにチェックアウトされていたら先にワークツリーを消す。
   `gwq` があれば `gwq remove -b <branch>` を使う
   (ワークツリーの管理主体を gwq に一本化するため。[[git-worktree]] と同じ理由)
2. ブランチは **常に `git branch -D`**
3. `--remote` を付けたときだけ `git push origin --delete <branch>`

**`git branch -d` は使わない。** `-d` が見るのは「**HEAD**(かその upstream)に入っているか」で、
`--base` に渡した取り込み先ではない。`--base <親ブランチ>` のように HEAD 以外を指定すると、
取り込み済みでも "not fully merged" で必ず拒まれる(2026-09-08 実測。`merge/` へ取り込んだ
`sub/` を消そうとして、ワークツリーだけ消えてブランチが残った)。見るべきは `--base` への
取り込みで、それは上の 3 段の突合で確定している。

**1 本の失敗で残りを放置しない。** ブランチごとに独立して処理し、失敗しても次へ進む。
末尾に「最後まで片付いた件数」と手当てが要るブランチ名を出し、終了コード 1 で終わる。
`set -e` のまま 1 本目で落ちると、ワークツリーだけ消えてブランチが残り、2 本目は
手つかず、という一番始末の悪い状態になるため。

**gwq の戻り値を信用しない。** `gwq remove -b` は途中で失敗しても終了コード 0 を返し、
登録・ディレクトリ・ブランチが中途半端に残ることがある(実測: ワークツリー登録は外れたが
ディレクトリの一部とブランチが残った)。スクリプトは戻り値ではなく
「登録が消えたか」「ディレクトリが消えたか」「ブランチが消えたか」を実地で確認し、
残っていれば `git worktree remove --force` / `git branch -D` で始末する。

ディレクトリの残骸を `rm -rf` するのは、**`.git` がファイルで、その `gitdir:` 先が既に無い**
(= git から切り離された残骸であることが検証できる)ときだけ。それ以外は警告を出して手を出さない。

## 対象から外れるもの

- `main` / `master` / `develop` と base 自身
- 実行中のワークツリーがチェックアウトしているブランチ(自分の足元は消せない)
- `--pattern` に一致しないブランチ。既定は `@(種別)/+([!/])`(分割しない作業)、
  `@(種別)/+([!/])/main`(親ブランチ)、`@(種別)/+([!/])/sub/@(種別)/+([!/])`(サブブランチ)
  の 3 つなので、旧ルールの `[名前]/[種別]`・`[名前]/sub/...`・`sub/*`・`merge/*` や
  スラッシュを含まない名前は明示しない限り触らない。
  ただし旧ルールの親ブランチで名前が種別と同じ語のもの(`docs/fix` など)は区別できず拾う。
  パターンは bash の `case` で評価する(`*` はスラッシュを跨ぐ。extglob 有効)
- `spike/*` と `wip/*` は**名指ししたときだけ**対象にする。`--pattern spike/feature/foo` のように
  ブランチ名をそのまま渡したときに限り、`--pattern '*'` や `--pattern 'spike/*'` のような
  glob で一致しても `SKIP` で残す。spike は実験、wip は作業途中の置き場で、取り込み判定が
  「作業が済んだ」ことを意味しない。特にコミットを積む前のブランチは先端が base と同じ位置に
  あるため、`ancestor` で取り込み済みと判定され、glob でまとめて拾うと消えてしまう。
  `spike/feature/foo/sub/fix/x` のような接頭辞付きのサブブランチも同じ扱い
- コミットを積む前の親ブランチ・サブブランチも `ancestor` で `DELETE` に並ぶ。
  `--apply` の前に dry-run の一覧で確かめる

## 注意

- リモート削除は取り消せない。`--remote` を付ける前に必ず dry-run の一覧を見せて合意を取る
- **実機確認が残っている作業のブランチは消さない**。main にマージ済みでも、
  VVD 反映などの検証が終わるまでは差し戻し先として残す運用になっている
